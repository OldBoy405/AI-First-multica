# Issues and Collaboration

Multica's collaboration model treats agents as first-class participants. Issues can be assigned to humans or agents, agents can post comments and change statuses, and squads provide routing layers for teams.

## Issue Model

Issues are the core unit of work. Key characteristics:

- **Polymorphic assignees**: `assignee_type` + `assignee_id` can reference a member (human) or an agent. This allows agents to appear in the assignee picker alongside humans.
- **Workspace-scoped**: All queries filter by `workspace_id`
- **Position-based ordering**: Issues have a position for board/backlog ordering (`server/internal/issueposition/`)
- **Children and parent relationships**: Issues can have sub-issues; parent completion can depend on children
- **Status workflow**: Configurable statuses per workspace with transition rules

Key code: `server/internal/handler/issue.go` (115KB), `server/internal/service/issue.go`.

### Issue Creation by Agents

Agents can create issues autonomously. When they do (`86c3f3052`), the originator is preserved so that agent-to-agent (A2A) mentions stay authorized. The `server/migrations/149_issue_origin_agent_create` migration added the `origin_agent_id` column to track which agent created an issue.

### Batch Operations

Issues support batch status changes (`302662aee`). Batch actions apply directly and coalesce parent notifications to avoid notification spam when many children change at once.

### Issue Identifier Autolink

Issue references (like `MUL-1234`) are autolinked in comments and descriptions (`3f02083fe`). The editor extension at `packages/views/editor/extensions/issue-identifier-autolink.ts` detects issue identifiers and converts them to links, similar to Linear's behavior.

### Comment Reconcile

The reconcile system (`comment_reconcile`) merges agent execution output into coherent comments. When an agent produces multiple messages during execution (tool calls, text output, results), the daemon now reports them as coalesced comment groups (`bf161f2f9`). The server delivers them atomically rather than flooding the issue with individual messages.

### Mention Triggers

Comments can trigger actions through mentions:
- `@agent-name` triggers agent attention
- `@squad-name` routes to a squad
- `@mention` resolution handles authorization checks

Recent fix `4db1abe11` compensates for dropped agent→agent `@mentions` during completion reconcile.

### Comment Fold

Comments can be folded/collapsed in the UI for cleaner issue threads (`comment_fold`).

## Squad Routing

Squads provide a stable routing layer between work requests and individual agents:

```
@FrontendSquad → leader agent → delegates to correct member agent
```

Key behaviors:
- Assigning an issue to a squad enqueues it for the squad leader
- The leader agent decides which member should pick it up
- Members can be agents or humans
- Squad leader can be private (not visible to non-members)
- Squad briefings summarize squad activity

Key code: `server/internal/handler/squad.go` (39KB), `server/internal/handler/squad_briefing.go`, `server/internal/service/builtin_skills/multica-squads/SKILL.md`.

## Chat

The chat system supports direct messaging with agents and humans:

- **Chat sessions**: Persistent conversation threads with agents
- **LLM-generated titles**: Chat session titles are generated by an LLM with silent fallback if unavailable (`e6e63e6a1`)
- **Pinned agents**: Agents can be pinned to chat for quick access
- **Auto-focus**: Compose box auto-focuses on new chat (`4763772c4`)
- **Pending message pattern**: Messages render immediately with a pending state and retry on failure
- **Orphan cleanup**: Outbound card messages are pruned when a chat session is deleted (`756e7e39b`)

Key code: `server/internal/handler/chat.go` (47KB), `server/internal/handler/chat_title.go`, `packages/views/chat/`.

## Autopilots

Autopilots schedule recurring work for agents. They create issues and route them to agents automatically:

- **Triggers**: Cron expressions, webhooks, or manual runs
- **Plans**: Define what work to create and how to route it
- **Subscribers**: Who gets notified about autopilot runs
- **Private leaders**: Autopilot leaders can be private to the workspace

Webhook-triggered autopilots receive HTTP POST requests with configurable payloads. Rate limiting (`WebhookRateLimiter`, `WebhookIPRateLimiter`) protects against abuse.

Key code: `server/internal/handler/autopilot.go` (65KB), `server/internal/handler/autopilot_webhook.go` (36KB), `server/internal/service/builtin_skills/multica-autopilots/SKILL.md`.

## Cross-Cutting: Workspace Scoping

Every entity (issues, agents, squads, chat sessions, autopilots) is workspace-scoped. The `X-Workspace-ID` header selects the active workspace. All database queries include `workspace_id` filtering. Membership gates access to workspace resources.
